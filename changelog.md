# Changelog x5digital_dynamic_hc
## Решение проблем с `no_live_upstreams` при переходе на Nginx >= 1.30.1

В Nginx версии 1.30.1 (а также в ветках 1.29.x) появилось несколько серьезных архитектурных изменений, которые ломали логику модуля и приводили к ложному переходу upstream серверов в состояние `down`. 

### Описание проблем

1. **Изменение семантики флага `peer->down`**
   В новых версиях Nginx из коммерческой ветки NGINX Plus был перенесен функционал *Sticky Sessions / Draining*. Из-за этого поле `peer->down` перестало быть простым `0` или `1` и превратилось в битовую маску, где `8` означает состояние *draining* (плавный вывод ноды из ротации). Старый код модуля жестко присваивал `peer->down = 0` при успешном хелсчеке, тем самым ломая внутренний стейт-стейт машины Nginx и приводя к гонке за счетчик живых нод (`peers->tries`). Когда счетчик падал до нуля, Nginx стрелял алертом `no_live_upstreams`.
   
2. **Проблема ALPN в gRPC хелсчеках (HTTP/2)**
   В Nginx 1.29.4 появилась встроенная поддержка Application-Layer Protocol Negotiation (ALPN) для бэкендов. Модуль при этом устанавливал TLS соединение, но не отправлял ALPN `h2`. Современные gRPC/HTTP2 бэкенды стали отбивать такие запросы с кодом 400 Bad Request, из-за чего модуль не находил gRPC-сигнатуру ответа `SERVING` и помечал ноды как `down`.

3. **Ложные таймауты (WANT_READ/WANT_WRITE)**
   Во время TLS-хэндшейка (а также чтения/записи поверх TLS) на неблокирующих сокетах (`EPOLLET`) функциям из OpenSSL иногда требуется дождаться следующего I/O события. Код модуля в такие моменты просто возвращал `NGX_AGAIN`, но не перевешивал обработчики событий `c->read->handler` и `c->write->handler`, из-за чего сокет навсегда зависал, пока не срабатывал таймаут.

4. **Строгая валидация заголовка Host для IPv6**
   В 1.30.1 Nginx переписал парсер заголовка `Host`, который теперь строго следует RFC 3986. При генерации заголовка `Host` для IPv6 (например, `[fe80::1]:443`), парсер модуля отрезал строку по первому двоеточию (`Host: [fe80`). Nginx 1.30.1 немедленно отбивал такие внутренние запросы ошибкой 400, ломая хелсчеки.

### Что было сделано (Как пофиксили)

1. **Безопасная работа с `peer->down` и `peers->tries`**
   - Вместо жесткого присваивания `0` или `1`, теперь модуль использует побитовые операции (`peer->down &= ~1` и `peer->down |= 1`), чтобы модифицировать только младший бит (флаг `NGX_HTTP_UPSTREAM_FAILED`), сохраняя остальные стейты (например, *draining*).
   - Изменение счетчика `peers->tries` теперь делается атомарно через `ngx_atomic_fetch_add`, что полностью исключает race condition между воркерами Nginx.

2. **Поддержка ALPN для gRPC и HTTPS**
   В шаблоны HTTPS и gRPC добавлена функция `set_alpn()`, которая вызывает `SSL_set_alpn_protos` для установки корректного Application-Layer протокола во время хэндшейка (`h2` для gRPC и `http/1.1` для HTTPS). Теперь gRPC бэкенды корректно понимают протокол.

3. **Реализация TLS State Machine для неблокирующих сокетов**
   Во все переопределенные методы `on_ssl_handshake`, `on_send` и `on_recv` для `https.h` и `grpcs.h` добавлено корректное перенаправление обработчиков `read` и `write` при получении `SSL_ERROR_WANT_READ` и `SSL_ERROR_WANT_WRITE`. Это предотвращает "зависание" TLS-хэндшейка и ложные падения по `timeout`.

4. **Корректный парсинг IPv6 для SNI и Host**
   В функции парсинга домена перед хэндшейком исправлен поиск порта. Для IPv6 адресов учитывается наличие скобок `[` и `]`, поэтому порт обрезается корректно, сохраняя валидный адрес, который не отторгается новым строгим парсером Nginx 1.30.1.
